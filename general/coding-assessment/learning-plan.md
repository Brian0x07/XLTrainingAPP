# 在线测评 / 综合算法题训练专题

## 定位

这是一个按需打开的旁支专题，不纳入当前默认主线，也不改变原有 React -> React Native 的学习节奏。

这个专题用于训练知名外企和大型互联网公司常见的在线笔试 / 编程测评题，包括算法基础、输入输出、英文题面拆解和时间复杂度判断。

这类题通常有几个特点：

- 题面是英文业务故事，但核心多是数组、字符串、排序、查找、贪心、动态规划等基础算法。
- 输入输出格式严格，不能打印多余调试内容。
- 题目更看重完整可运行代码，而不是只写出大概思路。
- 数据范围经常较大，需要能判断是否会超时或溢出。
- Swift 环境可能偏旧，所以优先使用稳定、基础的 Swift 写法。

本专题默认用 Swift 单文件训练，贴近线上考试环境。

## 训练目标

每道题都按下面顺序训练：

1. 先把英文题面翻译成清楚的中文需求。
2. 圈出输入、输出、约束和样例。
3. 判断核心算法类型。
4. 先写函数版，保证样例通过。
5. 再补成标准输入输出版。
6. 复盘错误：变量名、边界、输出格式、Int/Int64、是否多打印。

## 难度安排

### beginner

目标：能稳定处理简单在线测评题。

重点：

- `readLine()` 基础输入
- 数组切片、排序、遍历
- 字符串拆分
- Dictionary 计数
- 边界值：空数组、`K = 0`、`K = N`
- 输出格式

练习文件：

- `beginner/01-array-sorting-and-counting.swift`

### intermediate

目标：能处理 `10^5` 级别数据，避免暴力双循环。

重点：

- 排序 + 前缀最大值
- 二分查找
- 前缀和
- 双指针
- 贪心选择
- `Int64` 防溢出

练习文件：

- `intermediate/01-sorting-binary-search-budget.swift`
- `intermediate/02-travel-platform-online-assessment.swift`

旅行/住宿平台综合题重点：

- API 返回结果过滤与排序
- 房间库存、入住退房区间、扫描线
- 评论关键词匹配与排序
- SQL 式 group by / 聚合 / top N 报表

### advanced

目标：能处理更综合的笔试题，并能在时间压力下拆题。

重点：

- 动态规划基础
- BFS / DFS
- 堆 / 优先队列
- 区间问题
- 图与依赖关系
- 快速输入器的使用场景

高级题不一次性全部生成，会根据 beginner 和 intermediate 的答题情况逐步补题。

## 建议节奏

这个专题按 `80% 主线 + 20% 旁路` 的比例安排，不抢 React / React Native 主线时间。

建议频率：

- 常规周：每周 2 次，每次 30 到 45 分钟，每次只做 1 道题。
- 忙碌周：每周 1 次，每次 30 分钟，可以只读题、复述题意和讲思路，不强求写完。
- 不建议连续多天刷题，除非临近笔试或面试。

推荐安排：

- 周中一次：beginner 简单题，训练英文题面拆解、输入输出、数组/排序/计数。
- 周末一次：intermediate 综合题，训练排序、二分、前缀和、贪心和复杂度判断。

推荐流程：

1. 先读题，不写代码，用中文复述题意。
2. 写出样例拆解过程。
3. 写函数实现。
4. 运行文件看测试输出。
5. 如果通过，再尝试改成标准输入输出。
6. 最后把错误点写进批改记录或补充笔记。

## 提醒规则

提醒应该轻量，不打断主线。

适合提醒的时机：

- 完成一个 React / React Native 小题或一个小模块之后。
- 用户询问“今天练什么”“接下来怎么安排”“最近进度如何”时。
- 距离上次 coding-assessment 练习大约一周，且当前主线没有明显阻塞时。

不适合提醒的时机：

- 用户正在处理 React / React Native 的具体报错或实现细节时。
- 用户只是说“继续训练”“继续做题”，但没有提到旁路专题时。
- 主线任务还没完成一次可批改的闭环时。

## Swift 线上考试注意点

- 普通题优先用 `readLine()`，更清楚。
- 数据量很大时，再考虑 `FileHandle` 快速输入。
- 题目保证输入合法时，`readLine()!` 和 `Int(...)!` 可以接受。
- 涉及 `10^9 * 10^9` 时用 `Int64`。
- 不要输出调试文字，线上评测会因为输出格式不一致判错。
- 变量名要前后一致，例如 `k` 和 `key` 不要混用。
